What boto3 does when a log file travels to MinIO

A visual explanation of the Python application, boto3, the S3-compatible API, MinIO, and what changes when boto3 is not used.

The one-sentence answer

Python decides what to archive. Boto3 turns that decision into authenticated S3-compatible network requests. MinIO receives those requests and stores the object.

Without boto3, the file does not magically reach MinIO. We must replace boto3 with another uploader, such as the MinIO CLI, AWS CLI, another SDK, or our own HTTP implementation.

1. First, separate the four names

Most of the confusion comes from treating the storage product, the protocol, and the client library as one thing.

The word s3 in boto3.client("s3") identifies the API language. endpoint_url identifies the actual server.

2. The archive flow in this project

The real-time Kafka path and the long-term archive path share the source log, but they have different jobs.

Fluent Bit should not be confused with the archiver. Fluent Bit streams records to Kafka; the archiver preserves completed files in MinIO.

3. What happens inside boto3?

The visible Python call is small because boto3 hides credential lookup, signing, HTTP transport, response parsing, and much of the retry behavior.

Credentials are not storage

Credentials are only proof of identity. They do not contain the file and they do not tell MinIO where to store it.

Bucket and object

A bucket is a named storage container. An object is the file data plus metadata, identified by its object key.

bucket: traffic-log-archive
key:    apisix/access-logs/access.log.2026-08-24
data:   the log file bytes

The key looks like a folder path, but it is really an object name with slash characters.

4. What changes when boto3 is removed?

Removing boto3 does not remove the need for an S3 client. It only changes which tool performs the protocol work.

7. Issue understanding

Expected understanding

Boto3 is a Python SDK for making S3 API calls. It can target AWS S3 or MinIO, depending on the endpoint configuration.

Actual confusion

The name “boto3” sounds AWS-specific, so it is easy to assume it cannot work with MinIO.

Divergence point

The apparent contradiction is at boto3.client("s3"): s3 is the API model, while endpoint_url chooses MinIO.

Root mechanism

MinIO implements the S3-compatible HTTP contract. Boto3 speaks that contract; it does not require the server to be owned by Amazon.

8. Applying it to the current repository

Confirmed The archiver is a separate Python service. It scans stable rotated files and uses a storage adapter backed by boto3.

Confirmed The Docker Compose configuration supplies the MinIO endpoint and credentials to the archiver.

Still needed The dedicated APISIX rotator must create completed access.log.* files. Until that exists, the archiver should find no eligible archive file.

Still needed Production credential management, object retention, and the policy for copying files to another long-term system remain deployment decisions.

9. Final mental model

APISIX creates the log.

The rotator closes the log.

Python decides that the closed file is ready.

Boto3 performs the authenticated storage conversation.

MinIO stores the object.
